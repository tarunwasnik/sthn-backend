## T6L-8G-A external dataset acquisition and inventory

`externalDatasetIntake.ts` adds a protected-source-free intake boundary for external labeled moderation datasets. It preserves raw downloaded artifacts below `dataset-research/text-moderation/external-datasets/<source>/raw/`, computes SHA-256 evidence, inventories CSV schemas/source-native labels/languages without emitting text, and publishes bounded per-source manifests plus one registry. It does not stage rows, map labels, deduplicate text, select samples, or import model/training/release code.

Run `npm run prepare:text-moderation:external-datasets` to publish the local preparation authority, then run `npm run acquire:text-moderation:external-datasets` on the laptop to perform the potentially large, resumable acquisition. Kaggle is deliberately recorded as `AUTH_REQUIRED` unless already-authorized credentials are explicitly integrated; no mirror is substituted. The external cache is ignored by Git. The intake guard refuses paths containing the frozen benchmark or INTERNAL_TEST markers. Disk diagnostics are informational only, and there is no RAM eligibility gate.

Staging rows import source facts only. STHN decisions, categories, mappings, duplicate/semantic groups, and final splits remain unresolved. `datasetVersion` is intentionally owned by a future immutable release manifest rather than repeated in construction rows; a future release export must inject it without changing `STHN_TEXT_MODERATION_DATASET_SCHEMA_V1` semantics.

The acquisition CLI considers only the four training-authorized registry entries in the frozen order. Multilingual HateCheck is registered solely to exercise the diagnostic guard and its rows are not acquired.

The non-mutating source-label mapping authority and audit requirements are documented in `MAPPING_POLICY.md`. Mapping previews return separate results and never write into provenance staging.
